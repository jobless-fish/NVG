# NODEVERSE 파이프라인 작업 현황

문서 갱신: 2026-11-10 / 실서버 검증 기준: 2026-11-09. 실시간 서버 가용성은 별도 점검한다.

## 구성
게임 서버 → PC2 수집 API(/v2/play-records) → Kafka → Spark 검증·중복 제거 → 영속 outbox → direct-writer → PC3 MySQL·MongoDB → 대시보드 조회.

- PC2: Windows + Docker, 192.168.0.81. 8000은 수집 API, 8010은 점검 화면.
- PC3: Windows 직접 설치, 192.168.0.167. MySQL nodeverse / MongoDB nodeverse_logs.
- 기존 /v1/events는 단일 로그용이다. PC3 자동 적재에는 관계 정보가 포함된 v2 규격을 사용한다.
- 비밀 설정과 실제 DB 파일은 이 저장소에 포함하지 않는다.

## 완료·검증 상태

| 영역 | 상태 |
|---|---|
| Kafka·Spark·원본·격리·영속 대기열 | 구현 및 실제 경로 시험 완료 |
| 회원 UUID·관계 문서 직접 적재 | 실제 PC3 저장 확인 |
| 동일 전송/내용 충돌 | 원본 3건·정제묶음 1건·작업 1건·격리 1건 확인 |
| 조회 화면 | 로컬 로그 및 서버 MongoDB 읽기 전용 조회 구현 |
| 팀원 대시보드 | 사용자에게 표시 확인 완료 응답 받음 |
| 별도 물리 PC1 | 미검증. PC2가 송신 역할을 모의함 |
| 종료·시간 정책 | 미확정. in_progress는 시험 가정, 종료 자동 갱신 비활성화 |
| 원격 장애·복원 시험 | 대기열/재개 구현 및 로컬 시험. 실제 원격 중단 시험은 미실시 |
| AWS | 검토·목표 구성 작성. 배포/리소스 생성 미실시 |

실제 시험은 회원 1명과 문제·세션·실행·시도·이벤트 1세트를 저장했다. 약 6초는 단일 시험 관측값으로 SLA가 아니다. 테스트 데이터는 별도 식별자로 남겨두며 실제 사용자 통계를 대표하지 않는다.

## 다음 작업

1. 실제 PC1에서 v2 규격으로 송신하고 stored와 PC3 화면을 함께 확인.
2. 진행 중 상태값·이벤트 enum·종료·일시정지·재개 시간 규칙 확정.
3. 적재/조회 계정 분리, TLS·키 관리·방화벽 제한 확인.
4. 원격 DB 장애 재시도, 백업·복원, outbox/journal/checkpoint 복구와 경보 시험.
5. 부하·월 비용 산정 후 EC2 검증 환경 및 관리형 확장 여부 결정.

현재 MongoDB 무인증은 내부망 시험 조건이다. 공개 배포 전 인증·암호화 연결로 전환해야 한다. SQLite 진행표는 클라우드 작업자 재배치 시 영속 저장 또는 DB 이관 설계가 필요하다.
