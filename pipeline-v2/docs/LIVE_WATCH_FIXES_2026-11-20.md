# 실플레이 적체 개선 및 적용 결과 (2026-11-20)

## 적용한 변경

- earliest-due 방식으로 outbox를 선택해 낮은 sequence 재시도가 신규 로그를 굶기지 않도록 했습니다. 문맥 대기 재시도는 5~60초 백오프를 사용합니다. 선행 이벤트 처리 시 바로 다음 순서 대기 이벤트를 깨웁니다.
- 원격 Mongo 원본을 먼저 보존한 뒤 MySQL 회원 조회와 대시보드용 투영을 수행합니다. SQL 장애·회원 식별 실패가 원본 보존을 가로막지 않도록 했습니다. 같은 worker에서 순차 실행하므로 SQL 지연의 영향이 완전히 제거되는 것은 아닙니다.
- 문제/시도 시작 이전 이벤트, 연산 정보 누락, 이미 종료한 시도 이후 이벤트는 `pipeline_quarantined_events`에 원본·해시·사유를 보존합니다. 원본 archive도 유지합니다.
- 격리는 실제 도착한 **연속된 다음 sequence**에 대해서만 수행합니다. 격리 영수증을 기록한 뒤 그 순서를 소비합니다. 존재하지 않는 번호, ID 충돌, 모호한 회원 연결은 임의로 건너뛰지 않습니다. 정상 학습 이벤트 수에 격리 이벤트를 포함하지 않습니다.
- 상태 API에 queued_at, remote_archive_stored_at, completed_at, stored_at / quarantined_at, queue_to_terminal_ms를 노출합니다. quarantined는 stored와 별도 최종 상태이고 사유는 result.reason에 있습니다. 이 시간은 게임 발생부터 화면까지의 전체 지연이 아닙니다. 기존 원본의 archive 시각은 개선 코드가 처음 저장 응답을 확인한 시각이며 과거 최초 삽입 시각을 소급 복원한 값이 아닙니다.
- 감시 중 확인한 3개 설치 플레이어 ID는 사용자 확인을 받아 기존 nb 회원에 비공개 설정으로 연결했습니다. 설정·키·DB 비밀번호는 Git에 포함하지 않습니다.

## 기존 실플레이 159개 재처리 결과

- 원격 Mongo에서 159개 모두 동일 이벤트 ID·payload_hash로 원본 보존 확인.
- stored 114개 = 업데이트 원본 18 + 대시보드 학습 이벤트 96.
- quarantined 26개 = 문제 시작 전 이벤트 11 + operation 누락 14 + 종료 시도 이후 이벤트 1.
- waiting_context 19개: 한 세션의 sequence 7이 outbox에 없어 대기. 원본은 원격 보존되지만 대시보드 투영은 진행하지 않습니다. 송신·Kafka·Silver 격리 경로를 대조해 해당 원본을 찾고 재전송해야 합니다. 원천 PC가 전송하지 않았다고 단정할 수 없습니다.
- 실제 nb 화면에서 행동 로그 96건, 시작 26건(진행 26), 재시도 문제 3건 확인. problem_completed가 확인되지 않은 실행을 해결로 추정하지 않아 해결은 0건입니다.

## 검증

- V2 검사 48개, 브리지 검사 3개: 총 51개 통과.
- 공개 8000으로 새 정상 로그 9개를 순서를 섞어 전송하고 그대로 재전송: 전부 stored 확인.
- 잘못된 연산 → 정상 문제 시작 흐름, 연산 정보 누락 → 정상 완료, 격리 후 동일 재전송, ID 내용 충돌, 실제 누락 순서 대기, 재시도 공정성, 후속 순서 깨우기를 회귀 검사했습니다.
- `remote_quarantine_smoke.py --allow-live-writes`는 공개 8000을 통한 역순·중복 전송 및 격리/정상 처리를 재현합니다. 기존 합성 시험 회원 fixture가 필요하며 실제 원격 DB에 시험 기록을 생성합니다.

## 아직 게임 팀에서 수정할 사항

1. 최신 게임 저장소·브랜치·커밋·EXE가 어느 것인지 먼저 확인하세요. NVG 내 게임은 구버전일 수 있습니다. 이번 PR은 게임을 변경하지 않았으며 확인 없이 게임 파일을 덮어쓰거나 병합하지 마세요.
2. 로그인 서버의 회원 UUID를 player_id로 사용하고 설치 ID는 분리하세요. 비공개 매핑은 과도기 조치입니다.
3. 메뉴 이동/초기화 신호를 가짜 operation_succeeded로 보내지 말고 별도 이벤트로 정의하세요. 문제 시작 → 시도 시작 → 연산/힌트 → 시도 종료 → 문제 종료 규약을 지키세요.
4. operation/failure_reason을 채우고 누락된 원본은 같은 UUID·내용으로 재전송하세요. 같은 ID 내용을 고쳐 덮어쓰지 마세요. 수정된 내용은 명시적 정정·재투영 절차가 필요합니다.
5. 일시정지·실제 풀이 시간과 문제 종료 규약을 확정해야 합니다. 현재 active_ms/paused_ms를 임의 계산하거나 시도 성공을 문제 완료로 대체하지 않습니다.

원래 감시 보고서의 ‘행동 0건’은 수정 전 스냅샷입니다. 현재 상태는 본 문서를 우선 참고하세요. 장시간 감시는 사용자 요청으로 종료했으며 이번 배포·검증만 수행했습니다.

추가 공개 경로 격리 시험도 통과했습니다. 6개를 역순 및 중복 전송하여 정상 4개는 gameplay_events에, 잘못된 2개는 격리 컬렉션에 저장되고 문제 실행이 완료되는 것을 원격 DB에서 확인했습니다. 원본 6개와 격리 이유는 보존했습니다. 상태 API로 각 최종 상태를 확인했습니다. 최종 검증에서 기존 실플레이 nb는 세션 24개·문제 실행 26개·행동 96개였으며 19개 순서 대기는 유지했습니다.
